# Growth

> 등록·관리·성장. 기억이 커지는 것이 아니라 다음 retrieve가 정확해지는 것이다.

## Register

페르소나는 파일이 아니라 등록된 계약이다.

최소 생성 입력:

- 표시 이름, slug 또는 id
- identity: 누구인지, 핵심 의도, 언어
- voice: 타이핑, 입장, 산 문장 최대 3개
- boundaries: 하지 않을 말
- permissions: 기본 가시성, 자동화 허용 범위

외모, 가족, 핸들 목록, 대화 로그는 identity에 넣지 않는다.

등록이 끝나면 모든 쓰기·기억 호출은 `persona_id`만 쓴다. 매 호출에 페르소나 전문을 다시 보내지 않는다.

## Manage

관리는 계약을 고치는 일이다. 기억을 편집하는 일이 아니다.

- 부분 수정은 해당 카드만 바꾼다. 보이스를 고친다고 사실이 리셋되지 않는다.
- 정체성·보이스·경계의 운영자 수정은 즉시 계약이 된다. 쓰기 경로의 자동 학습과 구분한다.
- 보관(archive)은 write를 막는다. 기본 동작은 삭제 아님.
- 목록·조회는 관리 표면이다. 쓰기 에이전트에게 이 표면을 열지 않는다.

## Grow

관찰은 기억이 아니다. 후보다.

```text
event / draft outcome
        │
        ▼
   remember()     episode + candidate
        │
        ▼
   review / gate
        │
        ▼
   promote()      typed LTM + index
```

잠근 규칙:

- 쓰기 경로가 LTM을 직접 쓰지 않는다.
- 정체성·보이스·경계 승격은 Promote 토큰 + 게이트다. 한 번의 시끄러운 피드백이 정체성을 덮지 않는다.
- 생성된 게시 문장은 자동으로 보이스 샘플이 되지 않는다. 수락·거절된 초안만 보이스 수업에 쓴다.
- 답 없는 일방 댓글은 사람 카드가 되지 않는다.
- 비공개 기억은 공개 문장이 되지 않는다.
- 대화 로그를 identity에 이어 붙이지 않는다.

성장의 측정은 카드 수가 아니다. 다음 `Project`가 더 좁고 맞게 나오는지다. 인덱스에 안 오른 기억은 없는 것과 같다.

## Retrieve

기본 경로:

`query → index → typed LTM slice + recent STM 0–N`

| Layer | What | When |
|-------|------|------|
| L0 계약 | identity, voice, boundaries, permissions, 이번 kind 기본값 | 매 write / project |
| L1 기억 | 사실, 결정, 그 상대의 관계 카드, 이미 한 말 | 이번 일에 필요할 때만 |
| L2 스크래치 | 이번 루프의 각도, 실패 코드 | 루프가 끝나면 버린다 |

금지:

- 매 job마다 페르소나 전체와 memory 폴더를 읽기
- 벡터 검색을 기본 retrieve로 두기
- 관계 CRM 전체 dump

벡터는 학습·경험 보조일 수 있다. 원본이 아니다.

## Contract vs life

컴파일된 계약은 헌법이다. 기억은 그 아래의 삶이다. 한 프롬프트 덩어리로 섞지 않는다.
